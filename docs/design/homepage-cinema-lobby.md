# LibreTV 新首页设计基准：影院大堂 + 意图画布

状态：设计冻结（2026-11-04）

## 产品定位

**第一眼看到 Friday，第二眼看到电影。**

首页采用「影院大堂 + 意图画布」结构：Friday 是明确的 AI 主入口，但不能占满手机首屏；用户打开页面时必须同时意识到下方有可浏览的影视内容。

本文件是新首页重构的设计与验收基准。它只冻结设计，不代表本阶段已修改生产首页、启用 Feature Flag 或部署。

## 手机端首屏

从上到下：

1. 品牌 LOGO / 顶部导航
2. Friday 品牌标识：FRIDAY · AI ASSISTANT
3. 主标题：「今天想看什么？」
4. 说明：「说出你想看的内容，Friday 帮你寻找」
5. 全息球与语音入口：「点击开始语音」
6. 传统文字搜索框：「搜索电影、电视剧、动漫…」
7. 快捷搜索词：蜘蛛侠、科幻、悬疑、动漫
8. 「今日热门」标题及真实影视海报列表

**首屏硬约束：**顶部导航完整可见；Friday 球体、标题完整可见；语音与文字搜索入口可操作；「今日热门」标题完整可见；第一排海报上沿必须进入首屏，理想露出海报高度的 20%–30%。

## 手机端滚动内容

首页内容继续向下浏览，至少包含：

- 今日热门
- 热门电视剧
- 动漫与综艺
- 分类浏览区域

内容必须来自 LibreTV 现有数据接口或已配置的推荐数据源，不用静态演示海报替代真实数据。

## 手机端尺寸与布局约束

以视口高度动态适配，不把单一像素值当作所有设备的固定布局：

| 模块 | 目标尺寸 |
|---|---:|
| 顶部导航 | 48–56px |
| Friday 标题与说明 | 58–72px |
| 全息球 | 112–140px |
| 语音入口 | 48–56px |
| 搜索框 | 48–52px |
| 热门搜索词 | 30–36px |
| 模块间距 | 8–14px |
| Friday 主视觉及搜索区域 | 45–55vh |

45–55vh 只计算 Friday 主视觉及搜索区域，不包含下方影视内容区。实际布局还需适配小屏高度、刘海屏与安全区。

## 桌面端

- 导航：品牌 LOGO、首页、电影、电视剧、动漫、综艺、历史等入口。
- Friday 主视觉：FRIDAY · AI CINEMA、「今天想看什么？」及影视搜索入口。
- Friday 区控制在约 55–65vh，影视内容紧接其后，不让推荐区被推得过远。
- 桌面端可放大全息球和留白，但不改变“先 Friday、后电影”的信息层级。

## 功能与架构冻结边界

本轮允许重构首页布局、Friday 球体展示与交互状态、麦克风入口视觉。

以下既有能力必须保持兼容，不得因首页重构而改写或绕开：

- 原有搜索业务逻辑
- `?q=` 与 `?s=` 搜索 URL 兼容协议
- 影视资源搜索 API 与数据源配置
- 推荐数据 API、真实海报与图片代理/回退逻辑
- 影片详情、详情跳转、播放器与播放控制
- 品牌正式名称 LibreTV
- Friday 语音与聊天会话的单一协调入口

新版必须由独立首页组件及 Feature Flag 控制；旧版继续作为回滚路径。先在独立分支开发，后续测试环境验证和灰度发布需要另行授权；本阶段不部署 Preview 或生产环境。

## 五项最终验收条件

1. 手机首屏出现「今日热门」标题及第一排海报上沿，理想露出 20%–30%。
2. Friday 麦克风入口真实调用浏览器语音识别/麦克风权限，不是只有动画。
3. 用户拒绝麦克风权限后，文字搜索仍能正常工作。
4. Friday 解析失败或语音不可用时，自动保留/提供传统搜索路径，不阻断用户。
5. 新首页热门数据、海报、详情跳转继续使用 LibreTV 原有业务接口和数据链路。

## 仓库盘点结论（基于当前分支代码）

### 已有基础

- `src/app/page.tsx` 已有 `NEXT_PUBLIC_HOME_V2` Feature Flag；V2 通过 `HomePageV2` / `HomeContent variant="v2"` 复用原有搜索、推荐、详情弹窗与页脚。
- `src/components/friday/FridayHero.tsx` 已有 Friday 首页入口；语音通过 `toggle-friday-panel` 事件交给唯一挂载的 `AIFloatingBall`。
- `src/components/home/HomeSearchSection.tsx` 已支持传统搜索、历史下拉与快捷搜索词。
- `src/components/douban-section.tsx` 已提供豆瓣推荐、Bangumi 每日放送、影视热榜三类推荐展示，并通过现有 API 与卡片组件获取海报。
- `src/app/api/search/route.ts` + `src/lib/search.ts` 提供原有点播源聚合搜索、流式结果、超时与安全校验。
- `src/app/api/douban/route.ts`、`src/app/api/hot-list/route.ts`、`src/app/api/bangumi/calendar/route.ts` 提供推荐数据接口。
- `src/app/api/detail/route.ts` 与既有详情组件负责点播源详情和播放数据；Friday 详情事件由首页协调器接收。
- `src/components/header.tsx` 同时挂载 Friday 助手与站点导航；V2 隐藏浮动球但保留助手面板实例。

### 当前与冻结规范的差距

- 当前 V2 Friday 区手机端为 `clamp(236px, 34svh, 310px)`，全息球约 116px；搜索框和快捷词位于独立搜索区，不能仅凭现有高度宣称达到 45–55vh 的组合目标。
- 当前 V2 仅渲染一个「今日热门」标题，下面沿用用户设置的单一推荐源视图；尚未形成“今日热门 / 热门电视剧 / 动漫与综艺”的分区浏览结构。
- 当前推荐卡点击主要调用 `onPick(title)` 进入站内搜索，并非直接打开推荐项详情；如要实现详情直达，必须先确认现有数据模型能否安全映射到详情资源，不能伪造点播源 ID。
- 当前手机端推荐卡片网格为 3 列起步；需要结合海报首屏露出目标重新设计卡片布局和密度。
- 当前桌面 Friday 区 CSS 为 58svh（最大 65svh），与桌面目标基本吻合，但导航内容和响应式信息层级仍需整体核对。
- 当前 `HomeContent` 同时承担搜索、源健康状态、推荐入口、详情事件和页面布局协调；新组件应拆分展示层，不复制第二套搜索或数据业务逻辑。
